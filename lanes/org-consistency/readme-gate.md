# Vendored README gate

Provenance: `caty-ai` skill `readme-standard`, sections “Core structure” and
“Required gate before making public”, manually vendored on 2026-08-26.

Update notice: whenever the source skill changes either section, manually compare
the source with this file, preserve stable item numbers where the meaning is
unchanged, update changed criteria, and record the new vendoring date above.

This is the README-only subset that a seat can decide from the four supplied
README files. Repository settings, Git history, contents of fenced code blocks,
executable command validity, community files, LICENSE contents, and issue labels
require evidence outside this launch and are intentionally not represented as
pass/fail items here.

## Numbered checklist

1. The document starts with one concise level-one project title. (Core item 1.)
2. A header block contains a badge row; the Core item 2 language-navigation requirement is evaluated only under item 15. (Core item 2.)
3. The opening gives a plain-language one-to-three-sentence explanation of what the project does, the problem it solves, and how it solves it. (Core item 3.)
4. A hero image is present near the top of the README. (Core item 4 and public gate item 2.)
5. A table of contents is present when the README is longer than two ordinary screenfuls. (Core item 5.)
6. A features section presents concise feature leads with supporting explanations. (Core item 6.)
7. A supported-environments table is present. (Core item 7 and public gate item 1.)
8. An architecture section gives a one-line design principle, a main-module table, and a link to deeper technical documentation. (Core item 8.)
9. A quick-start section exists, with prerequisites, an installation path, minimum configuration, and a first invocation each present as a heading or lead sentence. Command-body validity is outside this gate. (Core item 9.)
10. A configuration section acts as an index from user goals to detailed documentation rather than embedding the complete reference. (Core item 10.)
11. A documentation index links readers to the available deeper documents. (Core item 11.)
12. A development-status or roadmap section states the project’s current status. (Core item 12.)
13. A contribution section links to `CONTRIBUTING.md`. (Core item 13.)
14. A license section links to `LICENSE`. (Core item 14.)
15. All four files `README.md`, `README.ja.md`, `README.zh.md`, and `README.th.md` are represented, and each has mutual language navigation near its start. (Public gate item 4.)
16. README text exposes no cleanup-only material such as raw test logs, internal handoff notes, family codenames, or personal filesystem paths; uses as organization, product, or repository names are excluded. (README-visible part of public gate item 5.)
